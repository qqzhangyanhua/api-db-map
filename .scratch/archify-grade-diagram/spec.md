# Spec: 成图对齐 Archify 品质（布线 / 构图 / 时序）

Status: ready-for-agent
Created: 2026-09-11
Base commit: 7aa98bd

## Problem Statement

用 api-db-map 分析真实后端后，产出的 `api-db-map.html` 在样例数据上还能看，一到十几个接口、十几张表就变成一团交叉的贝塞尔线，标签压在线上，字段级外键线无法辨认。时序图只有箭头，看不出谁在忙、忙多久。首屏是工具栏 + 画布 + 整张汇总表 + 浮层抽屉，读者得自己翻出结论。成图没法直接截图放进评审文档或群里——和它声称对齐的 Archify 成图差距明显。

另外模板里残留了某次若依项目的表名（`sys_user`、`sys_dept`、`ims_t_working_hours`、`@DataScope`）做标签缩写，会污染所有项目的时序图。

## Solution

保持数据驱动、自动布局的路线，不引入 Archify 的手工坐标 schema。只借它的三条纪律：

- 布线纪律：T·01 / T·02 的边改为正交折线，垂直进出卡片，平行边错开，标签垫底色胶囊。
- 构图纪律：首屏只留「图 + 说明 + 三张自动生成的结论卡」，汇总表降级进抽屉；T·01 超过约 12 张表时按 module 收成组卡，T·02 字段超 10 个折叠。
- 时序纪律：T·03 从 `sequence[]` 推出激活条、回程虚线、三段阶段带，参与者加副标题。

同时清掉模板里的业务硬编码，修首屏闪白、字体阻塞、列标题英文等小问题。

## User Stories

1. 作为后端评审人，我想在 T·01 上看到接口到表的连线垂直进出、互不穿过卡片，这样 20 个接口时仍能顺着线读出谁碰了谁。
2. 作为后端评审人，我想让每条边的 SQL 动词标签有底色、不压在线上，这样截图放大后仍可读。
3. 作为后端评审人，我想让同一接口指向同一分组的多条边在竖向通道里错开，这样读边和写边不会重叠成一条。
4. 作为 DBA，我想在 T·02 上看到外键线从子表字段行精确指到父表主键行，这样能确认字段级关系而不是表级猜测。
5. 作为 DBA，我想在 T·02 上表卡按 module 分列排布而不是自动换行，这样外键线走向可预期。
6. 作为读者，我想在表超过约 12 张时 T·01 默认收成 module 组卡并标出表数，选中接口后再展开涉及的表，这样大仓库不会一屏糊掉。
7. 作为读者，我想在 T·02 字段超过 10 个时优先看到主键、外键和被当前接口触碰的字段，其余折叠为「+N 更多」，这样能聚焦在有关系的字段上。
8. 作为架构师，我想在 T·03 上看到每个参与者的激活条，这样能一眼看出 Service 从第几步开始忙到第几步结束。
9. 作为架构师，我想让 T·03 的回程消息用虚线区别于请求，这样请求/响应的方向不靠位置猜。
10. 作为架构师，我想让 T·03 分成「入口 / 业务 / 落库」三段阶段带，这样能快速定位 DB 操作发生在请求的哪一段。
11. 作为架构师，我想在 T·03 的参与者框下看到副标题（handler 函数名、表所属 module），这样不用切回详情就能知道参与者是谁。
12. 作为任何项目的使用者，我想让时序图的消息缩写只基于通用规则（动词 + 表 + 列数），这样别的项目的表名不会出现在我的图里。
13. 作为汇报人，我想让首屏是一张图加两三句说明加三张结论卡，这样截图直接可以进评审 PPT 而不用裁。
14. 作为汇报人，我想让结论卡自动算出「有写操作的接口数 / 只读接口数」「被最多接口触碰的表」「uncertain 条数」，这样不用自己数。
15. 作为汇报人，我想让汇总表从首屏移进抽屉或折叠区，这样它不再抢图的位置，但需要时还能查。
16. 作为读者，我想让选中接口后的证据以一条横幅出现在说明区上方而不是浮层盖住图，这样对照证据时图仍可见。
17. 作为深色系统用户，我想打开 HTML 时不闪一下白底，这样体验和 Archify 一致。
18. 作为内网用户，我想在 Google Fonts 不可达时页面仍立即渲染并回退系统等宽字体，这样离线也能看图。
19. 作为中文使用者，我想让 T·01 列标题是「接口 / 数据表」而不是 `Interfaces / Tables`，这样整页语言一致。
20. 作为「信号流」预设的使用者，我想让写边更粗更亮、读边更淡，这样这个预设真的突出流向而不只是换色。
21. 作为技能维护者，我想让每次改模板后有自动化测试打开渲染结果并断言布线、激活条、结论卡存在，这样不会再靠肉眼回归。
22. 作为技能维护者，我想让 `visualization.md` 和模板行为一致，规范里写了的折叠、分组在代码里真的发生。

## Implementation Decisions

- 只改渲染模板和 `visualization.md`，不改 IR schema，不改 `render_html.py` 的注入方式，不改三个 Python 脚本的 CLI。
- 布线改为「自排坐标 + 正交路由」：T·01 左列接口卡、右列按 module 分组的表卡，坐标由渲染代码计算；边走「右出 → 竖向通道 → 左进」三段折线；同一竖向通道内的平行边按固定像素步进错开；标签放在竖向段中点，带画布卡片底色和细描边的胶囊。不引入 Archify 的 `via` / `channelX` / `labelAt` 手工控制。
- T·02 同样自排列（按 module 分列），外键边从子表字段行右缘/左缘正交连到父表主键行，方向由两卡相对位置决定。
- 缩放改为 SVG 与卡片共用同一变换容器，避免 CSS `zoom` 导致边与卡片错位；缩放键位和按钮保留。
- T·03 激活条：同一参与者连续出现在相邻消息的 from/to 中时合并为一条 bar；bar 颜色按参与者类型（接口绿 / 表紫）；回程判定为「无 `op` 且方向为从右向左」；阶段带按 Client→Controller 为「入口」、首条含 `op` 消息之前为「业务」、含 `op` 消息区间为「落库」，边界不足时退化为不画带。
- 参与者副标题：Controller 用 `handler.file`，Service 用 `handler.fn`，表用 `module || schema`。
- 结论卡三张固定：读写接口计数、热点表 Top 3（按 `table_api_index` 长度）、uncertain 计数 + 前两条 evidence。全部从 IR 计算，不写 IR 里没有的话。
- 汇总表移出首屏：默认折叠在结论卡下方，点击展开；详情抽屉保留，选中项的关键证据改为说明区上方横幅，完整 evidence 进抽屉二级。
- 密度规则落地：T·01 表数 > 12 且无选中接口时按 module 渲染组卡，组卡显示表数量和 R/W 汇总徽标；T·02 字段 > 10 时按 PK → FK → 触碰字段 → 其余 排序，其余折叠。阈值写成模板顶部常量。
- 首屏主题：`<head>` 内联脚本先读 `localStorage` / `prefers-color-scheme` 再设 `data-theme`；字体链接改为 `media="print" onload` 异步加载。
- 删除时序标签缩写函数中所有项目相关分支，只保留通用截断：动词 + 表名 + 「N 列」。
- 「信号流」预设：写边加粗、读边变细并降低不透明度；其余预设不变。
- `visualization.md` 同步更新，删掉与实现不一致的描述。

## Testing Decisions

- 好的测试只断言渲染结果，不断言内部函数：给一份 IR，打开渲染后的 HTML，检查 DOM / SVG 长什么样。
- 接缝唯一：`render_html.py` 产物在无头浏览器中渲染完成后的页面。不新增第二个接缝，不把布线算法抽成独立模块单测。
- 断言内容：
  - T·01 所有边 `path` 的 `d` 只含直线段（M / H / V 或 L 且逐段水平或垂直），没有 C 曲线；每条边有对应标签胶囊。
  - T·02 外键边的起终点 y 坐标分别落在对应字段行的垂直范围内。
  - T·03 每个参与者至少一条激活 `rect`；无 `op` 的反向消息带 `stroke-dasharray`；存在三段阶段带元素。
  - 结论卡三张存在，计数与 IR 手算一致。
  - 使用 13 张表的 IR 时 T·01 默认渲染组卡而非表卡；使用 12 字段以上表的 IR 时 T·02 出现折叠行。
  - 页面文本不包含 `sys_user`、`sys_dept`、`ims_t_working_hours`、`@DataScope`。
  - 首屏 `<html data-theme>` 与预设偏好一致。
- 测试夹具：现有 `sample-ir.json` 加两份小 IR（一份 13 表、一份含超 10 字段表和无 `op` 回程消息）。
- 先例：仓库没有任何测试，无先例。需新增 Node devDependency（Playwright 或 Puppeteer）和一个 `pnpm test` 入口；依赖用 pnpm 安装。

## Out of Scope

- Archify 的 Story 章节、阅读深度分级、Presentation、WebM 录制、Semantic Radar、品牌图标。
- PNG / SVG / Share Card 导出（值得做，独立成下一个 spec）。
- IR schema 变更、Python 脚本变更、handler 追踪逻辑。
- Mermaid 兜底 `api-db-map.md` 的样式。
- 手工坐标覆盖能力。

## Further Notes

- Archify 的布局是 Agent 手写坐标 + 校验器兜底；我们是数据驱动自动布局。能借视觉结果，不能借布局算法，正交路由必须自己写。这是本 spec 唯一需要真正写算法的地方。
- 建议实施顺序：删硬编码 → T·01 正交布线 → T·03 激活条 → 结论卡 + 汇总表降级 → 密度折叠。测试基建在第一步同时搭。
- 每步完成后用 `sample-ir.json` 出一版和当前 `sample-preview.html` 对比。
